# Handler / Flow / Pipeline 迭代说明

本文是改造说明，不替代 PRD。

## 统一口径

```text
Handler（算子）= 最小执行单元
Flow = 可登记、可复用的 Handler 组
Pipeline = 编排好的业务链路，可包含 Flow、Handler 和内联步骤
```

tc-hawk 当前的 `aigc.Flow` 是旧研发模型，迁移时先作为 Pipeline 候选。历史上拆开的多个旧 Flow 允许归并为一条新 Pipeline；没有人工确认时，不按名称猜测，也不自动降级为新 Flow。

## 当前前端改造

- 目录拆成“算子 / Flow / Pipeline”。
- Handler、Flow、Pipeline 使用独立数据类型和详情视图。
- 当前已导入 54 个 Handler、0 个已确认 Flow、234 个 Pipeline 候选。
- 删除无来源的周运行量、假 CRUD 和假血缘关系。
- 成本与资源统一显示“待统计（占位数据）”。
- Handler 测试面板已实现 TOS 多行输入、非法路径和 20 条上限校验；真实提交等待后端 API。
- 普通用户发布包不包含源码路径、提交哈希和未解析 Go 常量引用。
- 桌面端使用双栏详情，移动端在列表和详情之间切换。

## Git 迭代方式

- 当前分支：`codex/handler-flow-pipeline-refactor`。
- 生成文件提交进 Git，但只允许通过 `scripts/` 重建，不手改。
- 每个 PR 同步提交契约、生成脚本、数据产物和界面改动。
- PR 自动执行 lint、类型检查和静态构建。
- 涉及旧 Flow 归并时，PR 必须列出来源映射和业务确认人。
- `main` 保持可发布，由现有 GitHub Pages 工作流发布。

## 仍依赖外部条件

- 旧 Flow 到新 Pipeline 的多对一归并清单。
- 目录 CRUD API、数据库和管理员权限。
- Handler 测试环境 API、鉴权和网络边界。
- 真实成本与资源统计口径。
